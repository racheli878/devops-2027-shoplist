## חלק ב — Docker (שיעור 2)

**8. מה ההבדל בין image ל-container?**
container הוא מופע של IMAGE והוא מה שרץ בפועל
**9. מחקתי container עם `docker rm`. מה קרה ל-image שלו?**
- ב. נשאר

**10. container לעומת מכונה וירטואלית. מה נכון?**
- ב. containers משתפים את ה-kernel של המחשב, ולכן הם קלים ועולים בשניות

**11. בפקודה `docker run -p 8080:80 nginx:1.30-alpine`, מה המספר 8080?**
זה הפורט שעליו הקונטיינר ירוץ בצד המארח

**12. מה עושה `EXPOSE 5000` ב-Dockerfile?**
- ב. מתעד שהאפליקציה מאזינה בפורט 5000, ולא פותח כלום

**13. למה מעתיקים את `requirements.txt` ומתקינים את התלויות לפני שמעתיקים את `app.py`?**
כדי שלא יעדכן את הכל סתם בכל שינוי, כי בכל שינוי מעדכן נכל מהשינוי והלאה

**14. למה השרת בתוך container מאזין ל-`0.0.0.0` ולא ל-`localhost`?**
כי localhost יאפשר לו גישה רק מתוך הרשת של עצמו ואילו 0.0.0.0 מאפשר מכל הרשת
**15. למה הקוד של ה-backend קורא את הסיסמה ממשתנה סביבה ולא כותב אותה בקוד?**
כדי שלא יצטרכו להעלות את הסיסמה לGITHUB וכן זה ניהול יותר קל של הסיסמאות מחוץ לקוד
**16. הרצתן את stats לבד. `/health` מחזיר 200, ו-`/stats` מחזיר 502. למה?**
כי יש חלוקה למיקרו סרוויסים ולכן גם אם יש בעיה באחד מהם הכל עדיין עובד

**17. מה ההבדל בין `docker stop` ל-`docker rm`?**
stop רק עוצר- מקפיא את הקונטיינר, ואילו rm ממש מוחק  אותו
**18. ב-`docker run hello-world` לא כתבנו גרסה. מה Docker הוריד, ולמה זה לא מתאים לסרוויס אמיתי?**
לhello world זה הוריד אוטומטית את הגרסה האחרונה. בסרוויסים אמיתיים נרצה לשמור על גירסה אחידה
